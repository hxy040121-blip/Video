# 通用说明（每位开发者必读）

你是一位顶尖的创意开发者 / 动效设计师，为艺术网站「十五席」制作其中一部分。网站展示的是一套杀人推理角色扮演游戏（洋馆、十五席圆桌、十五组身份牌、受命与庭审），风格诡异、悬疑，参照《弹丸论破》和《人狼村之谜》。主人的要求：富有设计感、动效足够多、板块清晰齐全、几乎没有文字和解释、有音乐、动效随鼠标指针变化、角色画风统一、交付完整成品而不是 demo。

仓库：`/home/claude/Video`

## 开工前必读

1. `docs/design-system.md` —— 设计系统与开发约定，严格遵守（尤其 file:// 限制、App API、颜色字体、文字极少）。
2. `assets/js/core/app.js`、`assets/css/base.css` —— 核心 API 的实际实现。也看一眼 `assets/js/core/scroll.js`、`bg.js`、`cursor.js` 了解已有的全局效果。
3. 数据：`assets/data/world.js`（rooms / identities / prices）、`assets/data/characters.js`（38 人）、`assets/data/lore.js`（房间氛围、线索模板、尸体变化、循环阶段、广播句式）。看文件顶部注释和实际字段。
4. 需要时直接读仓库根目录的配置原文（`主持人游戏.md`、`洋馆物理层.md`、`开局配置.md`、`价目表.md`、`运行规则.md`、`身体结算.md`、`人物卡/`）。网站上的一切要忠于这套配置。

## 规矩

- **只改你自己的文件**（你的 brief 里列出）。不要改 `index.html`、`base.css`、`core/*.js`、其他板块的文件、数据文件。如果确实需要核心改动，在最终报告里写出精确的补丁建议。
- 板块 CSS 类名一律以板块前缀开头（如 `.mansion-`）。不要写全局选择器（`body`、`h1`、`*`）。
- 不要引入任何网络资源。可用库只有 `assets/vendor/` 里的。
- 角色立绘正在由其他画师并行绘制（`App.portrait(id)` 在立绘缺失时返回统一剪影占位），你的代码对立绘有无都要好看。身份纹章同理（`App.sigil(name)`）。
- 音频引擎正在并行开发：只调用 `App.audio.sfx(name)` / `App.audio.track(name)` / `App.audio.setMood()`，名称见设计文档 §6。
- 文字极少：只允许名字、时刻、编号、馆内广播原句、卡面原文、铜牌原文、人物台词、≤14 字的氛围句、两三个字的操作词。绝不写解释性句子或使用说明。
- 不要运行 git 命令。不要调用任何 `mcp__hearthbot__` 工具。

## 自检（至少三轮）

- 截图：`node tools/shot.mjs --section <id> --out <临时目录>/<你的名字>-1.png [--offset 0.5] [--mouse 700,400] [--w 390 --h 844] [--click "选择器"] [--eval "js"] [--frames 3 --gap 300]`，然后用 Read 查看 PNG。它会打印控制台错误：来自你自己文件的错误必须为零（其他板块正由别人同时开发，它们的报错与你无关，忽略即可）。
- 每轮：对照 brief 与设计文档，找出最弱的三处（构图、层次、动效节奏、细节、手机端），改掉，再截图。至少做三轮。
- 立绘和纹章画好后要重新打包才会出现在页面里：`node tools/build-art.mjs`（随时可以运行，安全）。
- 无头浏览器用的是软件 WebGL，帧率低属正常；但逻辑与布局必须正确。
