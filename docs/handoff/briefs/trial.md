# 板块：庭审（trial）—— 可以玩的模拟庭审

你的文件：`assets/js/sections/trial-engine.js`（纯逻辑，不碰 DOM）、`assets/js/sections/trial.js`（画面与交互）、`assets/css/trial.css`，以及测试 `tools/test-trial.mjs`（用 Node 运行，验证引擎的结算规则）。

这是整个网站里唯一能「玩」的部分，也是展示「游戏」而不是「配置」的关键。它必须是**完整可玩、可以一直玩到只剩一人**的成品，规则忠于原文，演出有弹丸论破学级裁判的紧张感。

## 必读原文

`主持人游戏.md` 全文（尤其第一至五节、第七节广播句式、第八节金币），`开局配置.md`，`运行规则.md` 第 6 章，`洋馆物理层.md` 第 7、8 节（痕迹、尸体、观察耗时），`身体结算.md`（死因的身体表现）。`LORE` 里有整理好的线索模板（clueTemplates，含对角色属性的谓词）、尸体随时间的变化（bodyStages）、死因（causes）、广播句式。

## 玩法流程

0. **入局**：读取 `App.state.seats`（十五席，元素为角色 id 或 null）。少于 5 人时，提供「随机补满」（补到 15 人或 8 人，二选一按钮）。玩家点选一位在座的人作为「你」（或「随机」）。然后给你发一张身份牌（从 `WORLD.identities` 随机一组的正位，翻牌演出，用 `App.sigil`）——其他人也各自随机分到身份（隐藏）。监听 `cast:change`，席位变了就回到入局。
1. **受命与行凶**（不可见）：引擎随机选出受命者 = 凶手（不是你），和死者（不是你、不是凶手）。时间推进（屏幕上的时钟快速跳动）。若你是**先知**：在死亡时刻收到私人通知「有人死亡」（屏幕边缘一条极小的通知）——这给了你精确的死亡时刻。
2. **发现**：一名非凶手的人发现尸体——全屏闪粉、`discover` 音效、震动，广播：「发现尸体。调查时间一百二十分钟，于〈HH:MM〉在穹顶议事厅开庭。」（敲钟人：如果凶手的逆位是敲钟人，调查时间为三十分钟，广播用对应句式。）
3. **调查**（120 分钟，压缩为可玩的节奏）：
   - 案发现场：从 `LORE.rooms` 里挑一个 `crimeScene` 房间，按 `WORLD.rooms` 的真实尺寸画成俯视平面（墙、门、陈设轮廓），**一片漆黑，光标是手电**。
   - 尸体：画成粉笔轮廓/剪影（不血腥），点击查看：死因的体表特征（`LORE.causes[].sign`）+ 按死亡后经过的时间对应的尸体状态（`LORE.bodyStages`）。
   - 线索热点 3–4 个（真线索）+ 2 个无关的陈设（`LORE.rooms[].objects`，查看后是「没有异样」类的一两个字）。每次查看消耗馆内时间（按 `洋馆物理层.md` 第 8 节的耗时量级，5–20 分钟），120 分钟耗尽就强制开庭。一个巨大的圆环计时器显示剩余。
   - 线索生成：从 `LORE.clueTemplates` 中选出对凶手为真的变体，贪心地挑能排除最多其他人的那几条，直到嫌疑人（在座、存活、不是你、不是死者）剩下 1–2 人为止；最多 4 条。线索文字代入具体数值（如身高区间）。找到的线索变成「证物卡」收进屏幕下方的证物栏（弹丸论破「言弹」式的卡片，每张一个小图形 + ≤ 12 字）。
   - 你的身份若是**占卜家**：调查中可以查验一人，得知其当前正位身份名（被查验者会知道自己被查验了——用一句他的台词体现）。
4. **庭审**：在穹顶议事厅的圆桌——十五席环形排布，在座者是各自的肖像（`App.portrait`，视线追随光标；死者席空着并熄灭）。
   - **辩论**：从一号席起，每人发言一次（肖像亮起 + 台词气泡 `lines.statement`，或 `lines.accuse` 指向他怀疑的人，被指的人回一句 `lines.defend`）。每句约 1.5 秒，点击可跳过。凶手的发言会把怀疑引向符合部分线索的人。轮到你时，你可以选择「指认」某人（你的台词气泡）或「沉默」。
   - 你能在辩论中用的身份：**骑士**（公开揭发一人：对则主持人确认揭发成功；错则你永久失去投票权，被错指者此后投你时你额外受一票），**执行者**（公开发起特殊表决：指定对象获得的有效基础票超过存活在馆人数的一半即成为待处刑者；处刑后若非真凶，你永久失去投票权），**沉默者**（秘密封锁一人的正位能力至本场结束），**河豚**（选一个有人的席位，查询其左右相邻席是否有本批案件的真凶：「有」/「没有」）。
   - 主持人宣布：「辩论结束，开始投票。」（广播样式）
   - **投票**：从一号席起依次记名公开投票——投票者肖像亮起，一条红线从他射向被投者，被投者头顶的票数跳动（`vote` 音效）。轮到你时点选一人（可以投自己；弃票按自投结算）。你的身份若是**法官**：投票期间可秘密指定一人 +1 票；**倒吊人**：可把另一人投给你的一张基础票秘密反弹给原投票者（自投与能力加的票不能反弹）。AI 的**小丑**总票数自动 −1（隐藏修正，不公布发动者）。
   - 按原文结算顺序：①记录基础票 ②倒吊人反弹、法官/小丑/骑士修正 ③（国王：本模拟不发放逆位，可略）④确定结果。最终正票数唯一最高者形成有效选择；最高票不大于零或并列 → 未产生唯一有效结果。**首次并列：立即重投，并列者在紧接着的一次重投中不能投票但仍可被投。**没有并列而无结果：保持资格重投。**连续两次无法产生唯一有效结果，本批结束，不处刑。**
   - 产生唯一待处刑者后：若他是**白痴**且不是真凶，他公开身份撤销处刑并重新投票（本场剩余期间他不能投票也不能被投）；若他是真凶，能力失败并向全体确认其为凶手。**身怀希望之人**（不是待处刑者本人）可以公开身份撤销结果并立即重投，所有人不能选择刚才的待处刑者。你持有这两个身份时由你决定是否发动；AI 持有时用简单的策略。
   - 「表决选出待处刑者之后，任何人都可以说话」：待处刑者说一句 `lines.executed`。
5. **判定与处刑**：
   - 正确：「判定正确。〈某某〉是〈死者〉一案的凶手。」→ 处刑演出 → 本批结束。
   - 错误：先处刑被选中者，再公布「判定错误。〈某某〉不是〈死者〉一案的凶手。本场第一次误判。」→ 继续投票（回到投票）；本批第二次误判后结束，真凶逃过审判。
   - **处刑演出**：被选中者的肖像滑到画面中央，背景转为血粉 + 半调网点，巨大的「处刑」（`--f-brush` 或 `--f-display`），一道斜切的光/锁链的影子落下，闪白，肖像变成灰度并打上锈红的 ×（`execute` 音效）。不要血腥画面。如果被处刑的是你——你死了：画面黑下来，你的肖像倒下，可以选择「旁观」继续看完这局（不再参与投票）或「重来」。
6. **余波**：金币按第八节发放——每名存活者五枚出现在圆桌上自己面前（金币落桌的演出），查明时再各五枚；未查明时，凶手的十枚「出现在他套房的书桌上」（不广播，但你作为玩家可以在结算画面极隐晦地看到一个书桌上的光点）。你的金币累计，并 `App.bus.emit('trial:coins', 本局所得)`。然后「下一案」：存活者中重新指定受命者，循环。
7. **终局**：仍存活、在馆的人只剩一名时（可能是你），主持人实现其愿望：显示胜者肖像与 `lines.wish`，设置 `App.state.winner = id` 并 `App.bus.emit('trial:winner', id)`，提供滚动到终章（`#wish`）的按钮和「再来一局」。

## 引擎（trial-engine.js）要求

- 暴露 `window.TrialEngine`，纯函数式或明确的状态机，不依赖 DOM，可在 Node 里 `require`/`vm` 运行（文件末尾 `if (typeof module !== 'undefined') module.exports = TrialEngine`）。
- 随机数可注入（用 seed），便于测试。
- 投票结算、并列重投资格、连续无结果计数、误判计数、白痴、身怀希望之人、法官、小丑、倒吊人、骑士、执行者特殊表决、河豚查询、占卜家查验、先知通知、敲钟人 30 分钟、金币发放，全部在引擎里按原文实现。
- `tools/test-trial.mjs`：至少 20 个断言覆盖上面的规则（尤其：首次并列后并列者不能投票；无并列无结果保持资格；连续两次无结果结束；第二次误判结束；负票数保留不归零；最高票 ≤ 0 视为无结果；白痴是真凶时失败；身怀希望之人的重投排除原待处刑者；执行者的过半数含无投票权者计入总人数）。运行 `node tools/test-trial.mjs` 全部通过。

## AI 行为

- 公开的证物所有人都知道。每个 AI 对每个嫌疑人有一个怀疑度 = 符合线索的条数 + 噪声；`stats.readsPeople === '是'` 与 `observation === '擅长'` 的人噪声更小；`suspicion === '重'` 的人更爱指认；凶手永远不投自己，会投给最符合线索的非自己的人。
- 这样整体上真凶往往会被投中，但并不总是——你的那一票和你的身份能力能改变结局。

## 画面与节奏

- 这是一个**画面驱动**的游戏：几乎所有信息用图形表达（红线、票数、肖像亮灭、证物卡图形），文字只有台词、广播句、名字、两三个字的按钮（入座、开始、调查、开庭、投票、弃票、跳过、下一案、重来、旁观）。不要任何规则说明或教程文字——交互要直观到不需要解释（可点击的东西用光标形态和呼吸光提示）。
- 板块高度：固定一屏（`100vh`，`min-height: 680px`），游戏在里面切换场景（入局 → 现场 → 圆桌 → 处刑 → 余波），场景切换用 `App.slash` 斜切转场。玩游戏时不要被滚动打断：进入游戏后可以 `App.scroll.stop()`，退出（按钮「离席」，或 Esc）时 `start()`。
- 音乐：入局 `gallery`；调查 `investigation`；庭审 `trial`，投票时 `App.audio.setMood({tension: 1})`；处刑 `execute` 音效。
- `palette`：入局暗金；调查冷灰；庭审暗红；处刑血粉。`track: 'trial'`。
- 手机端：圆桌缩成两列网格或更小的环，现场的手电改为点击照亮。

## 自检

除了通用自检，还要用 `--eval` 驱动完整的一局（入局 → 调查 → 庭审 → 处刑 → 余波 → 下一案），每一幕截图检查。确认能一直玩到终局。

## 补充

- `character.canWalk === false` 的人（格里菲斯、乔尼）不能行走：他们不能被选为需要走到现场的凶手（除非死因是毒杀之类不需要移动的方式），也不能是需要走路的发现者。
- 线索模板的 predicate 是字符串表达式，用 `new Function('c', 'return ' + predicate)` 求值，已验证在 38 人上都能运行。
